Command line

A second launch of SonicScrewdriver.exe with a command hands it to the running instance (through a hidden window of the running app: no new background service) and exits with a code. The app must already be running; a command never starts it.

Commands

CommandDoes
--set <app> <0-100>Sets the app's volume (the maximum volume of the app still applies) and unmutes it when above 0
--mute <app> / --unmute <app> / --toggle-mute <app>Mutes, unmutes or toggles the app
--profile "<name>"Applies a volume profile
--mute-allMutes every app, or restores them (same as the shortcut)
--mic-muteMutes or unmutes the default microphone
--toggle-competitiveSwitches competitive mode

<app> is the exe name, with or without .exe (spotify and spotify.exe are the same). Examples:

SonicScrewdriver.exe --set spotify.exe 30
SonicScrewdriver.exe --mute discord
SonicScrewdriver.exe --profile "Game night"

Exit codes

CodeMeaning
0Done
1Unknown command or bad arguments
2Sonic Screwdriver is not running
3The app (or the profile, or the microphone) was not found (an app is found only while it plays sound)
4Refused because competitive mode is on (only --toggle-competitive works then, like the shortcuts)
5No answer

A short message is printed on the console that started the command (nothing is shown when started from a shortcut or a launcher).

Stream Deck, Touch Portal, AutoHotkey

  • Stream Deck: use an action that runs a program (for example System > Open, or a plugin that runs a command line) with the full command, such as "C:\Path\SonicScrewdriver.exe" --profile "Game night".
  • Touch Portal: use its action that runs an application, with the same path and arguments.
  • AutoHotkey: Run '"C:\Path\SonicScrewdriver.exe" --set spotify.exe 30', or RunWait to read the exit code.
